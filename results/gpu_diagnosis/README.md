# 两张 H100 在 MNIST KNN 请求中有多忙

2026 年 11 月 16 日在 SSH 别名 A100 对应的 Linux 服务器复测。两张卡均为同机的 NVIDIA H100 80GB HBM3。输入为 MNIST 全部 60,000 张训练图和 10,000 张测试图，每次请求计算 6 亿个查询与训练图之间的距离。距离使用 FP64，取 5 个最近邻，每张卡的查询批大小上限为 256。

## 端到端计时

从主机内存中的查询就绪计时，到主机收到全部预测标签停止。单卡处理 10,000 张，双卡各处理 5,000 张。四种配置均预热一次，随后交错执行，每种计时八次。表中为中位数，括号内为最小值和最大值。

| 训练集处理方式 | 单卡，毫秒 | 双卡，毫秒 | 单卡到双卡加速比 |
| --- | ---: | ---: | ---: |
| 每次请求重新上传 | 163.23（149.01–189.69） | 99.93（90.83–102.79） | 1.63× |
| 训练集和标签常驻显存 | 105.91（105.23–130.97） | 58.59（49.46–67.70） | 1.81× |

每张卡常驻 376,800,000 字节的训练图和标签。在已预热的 CUDA 环境中，同时给两张卡预装这份数据的一次实测为 40.86 毫秒。常驻版表中列出后续查询的耗时，每次仍上传查询图像、重算训练向量范数，并回传预测。双卡后续请求的耗时中位数下降 41.4%。全部 32 次计时和另 12 次进程追踪的输出均与已有 CPU 结果逐张相同，正确数均为 9,688。

## 哪些时间属于 KNN

另用 Nsight Systems 为该进程的四种配置各记录三次 CUDA 时间线。表中的百分比是三次请求内该 GPU 有本进程核函数记录的时长之和，除以三次端到端墙钟时长之和。同一卡上重叠的核函数区间只计一次。“两卡同时”取两卡核函数区间的交集。追踪会影响延迟，上表采用独立的常规计时。

| 双卡配置 | GPU 0 有 KNN 核函数 | GPU 1 有 KNN 核函数 | 两卡同时有 KNN 核函数 | 每卡每次主机传入 |
| --- | ---: | ---: | ---: | ---: |
| 每次上传训练集 | 44.5% | 47.4% | 36.9% | 408.16 MB |
| 训练集常驻 | 79.7% | 86.4% | 72.8% | 31.36 MB |

原版两卡平均各花 45.6 和 47.4 毫秒做主机到显卡的 CUDA 拷贝，常驻版分别为 3.25 和 3.31 毫秒。每卡少传的 376.8 MB 与训练图和标签字节数准确吻合。表中 MB 采用十进制。进程核函数的起止区间描述请求内的时间覆盖，区间内部的 SM 活跃度、实际访存带宽和峰值算力利用率仍未知。共享 GPU 的调度也会影响这些区间。

常规计时前的首条存盘样本显示，GPU 0 和 GPU 1 的整卡忙碌率分别为 99% 和 73%，功耗分别为 328 W 和 320 W。采样期间还分别有两个和一个其他计算进程。运行期间的整卡功耗和利用率包含这些任务，详见采样 CSV。NVML 将 GPU 利用率定义为采样窗口内有核函数执行的时间比例。[NVIDIA NVML 指标定义](https://docs.nvidia.com/deploy/nvml-api/620/api/structnvmlUtilization__t.html)

原作业的五次计时给出单卡 114.77 毫秒、双卡 78.66 毫秒，相应的 72.96% 由单卡耗时除以两倍双卡耗时得到。原实验的另一次 CUDA 分段测量显示，单卡计算阶段为 68.53 毫秒，双卡各为 34.64 和 34.55 毫秒，而双卡上传阶段仍各约 44 毫秒。两次实验的服务器负载不可直接比较。CPU 串行基线使用一个逻辑核，五次进程 CPU 时间与墙钟时间之比为 99.46% 至 99.48%。

## 数据和复现

- `timed/runs.csv` 和 `timed/summary.csv` 保存常规计时、吞吐量及预测一致性。`timed/metadata.json` 记录首次放置成本。
- `timed/boards.csv` 和 `trace_sync/boards.csv` 保存板卡利用率、功耗、显存以及其他计算进程数量，每 0.2 秒轮询一次。驱动报告的采样窗口可以跨越多次短请求。
- `kernel_timeline.csv` 保存逐卡逐次的核函数区间并集时长、双卡交集时长及上下行字节。`kernel_summary.csv` 汇总这 12 次请求。`trace_sync/runs.csv` 保存同一遍追踪时对应的端到端计时。
- `knn_sync.nsys-rep` 可在 Nsight Systems 图形界面打开。`knn_sync.sqlite` 是该追踪的可查询导出。分析程序核对主线程上的请求边界、各卡实际参与情况和双向传输字节。此处 Nsight Systems 2024.2.1 使用自带 CUDA 12.4 追踪库采集 CUDA 13.0 驱动上的活动。主线程 CUDA 边界与同次 Python 墙钟的最大测时差为 0.050 毫秒。

在服务器项目根目录运行以下命令，给复测选择新目录。

```bash
out=results/gpu_diagnosis_repeat
python3 -B diagnose_gpu.py --out "$out/timed" --repeats 8
nsys profile --sample=none --cpuctxsw=none --trace=cuda --output="$out/knn_sync" \
  python3 -B diagnose_gpu.py --out "$out/trace_sync" --trace --repeats 3
nsys export --type=sqlite --output="$out/knn_sync.sqlite" "$out/knn_sync.nsys-rep"
python3 -B analyze_gpu_trace.py "$out/knn_sync.sqlite" "$out/trace_sync/runs.csv" "$out"
```
